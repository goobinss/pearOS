# PEAR (A2P) launch checklist

1. Deploy both reviewed repositories using [DEPLOYMENT.md](DEPLOYMENT.md). Confirm backend health, authentication, matching content and all four pages on the public domain.
2. Choose the actual launch platform/network and confirm supply, launch terms, project fee rights/recipient, costs and claim mechanics before launching. A2P is the ticker, not a platform.
3. Verify a real read-only price source and implement it in Pear Core. The current live ratio intentionally remains unavailable; deploying or setting a URL does not enable prices.
4. Launch manually outside the repositories. Configure Pear Core with the exact network, RPC, explorer, contract, decimals, treasury and reviewed confirmation policy. Verify real reads and redeploy.
5. Run the public and private `pnpm check:launch` commands. Promote the verified public domain and exact contract once the announced features work.
6. Approve the policy prospectively, record actual eligible receipts and publish funded tasks through [CONTENT.md](CONTENT.md). Holder-related support requires reviewed published terms; no program is active now.

The 35% contributor / 25% support / 20% operations / 10% ecosystem / 10% reserve policy remains a proposal. Holdings, launch volume, market capitalization and expected fees do not fund it. Work approval, committed money and verified payments remain separate; payments are manual.

The community site can run and show prelaunch planning requests before these financial integrations are available. Confirm artwork rights and repository release controls before publication.
